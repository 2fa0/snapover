# Snapover 界面细节改动方案

状态：三项改动已于 0.6.2 实施，见 [更新记录](CHANGELOG.md#062)。本文保留当时的改动范围与验收要求，不代表已完成 Windows 实机验证。

目标：改善高频按钮的按压反馈、历史空状态、发送窗口拖放区，以及历史回写成功的反馈。分三次交付，每次都能独立回退。

## 1. 落地原则

1. **不进 `go.mod`**：CrychicUI 只作为写法参考，使用项目现有 MyGo v0.7.1。保持 `go.mod`、`go.sum` 不变，不引入音效依赖。
2. **不碰未提交的文件／文件夹协议**：保留现有剪贴板、校验、归档、缓存、传输、确认和历史持久化实现。涉及同一个 UI 文件时只叠加本方案必要的局部改动。
3. **不改窗口分页**：保持设置、连接设备、复制历史的页面结构、导航和窗口生命周期；允许为 Toast 增加必要的窗口关闭清理。

不升级依赖、不改版本号、不更换按钮种类。动效不延迟点击处理，也不增加后台常驻动画或定时任务。

参考来源：[CrychicUI](https://github.com/ELY-Open-Source/CrychicUI)，重点参考 `kit` 和 `files/Dropzone` 的写法。若直接复制上游代码，保留相应 MIT 版权与许可声明，不整包搬入。

## 2. 第一次交付：按钮按压与空状态

建议提交标题：`ui: 增加按钮按压和历史空状态动效`。

### 改动位置

- 新建 `cmd/snapover/motion.go`：只放 `press`、`arrive` 两个小函数。
- `cmd/snapover/ui.go`：在现有 `emptyState` 容器上应用 `arrive`。
- `cmd/snapover/window.go`：包装指定按钮，补历史空状态说明。
- `cmd/snapover/files.go`：只包装发送窗口指定按钮。
- `cmd/snapover/devices.go`：只包装配对指定按钮。
- `cmd/snapover/ui_test.go`：补按压与减少动态效果的回归覆盖。

### 实现约束

辅助函数保持以下规模，不增加配置、音效、悬停抬升或通用动效框架：

```go
func press(e ui.Element) ui.Element {
	p := ui.Pose{}
	if e.Pressed() {
		p.Scale = 0.97
	}
	return e.AnimatePose(p, ui.Snappy)
}

func arrive(e ui.Element) ui.Element {
	p := e.Keyframes("arrive", []ui.Keyframe{
		{Value: 1},
		{At: 180 * time.Millisecond, Value: 0, Ease: ui.EaseOut},
	})
	return e.Translate(0, 4*p).Opacity(1 - p)
}
```

以链式包装接入，保留原有按钮、标签、禁用条件及点击分支。例如：

```go
if press(ui.PrimaryButton(c, "复制").Disabled(busy)).Clicked() {
	// 原有操作。
}
```

包装范围限定如下，包含按钮在同一动作下切换的文字：

| 位置 | 按钮 |
| --- | --- |
| 主窗口历史操作 | 复制、置顶／取消置顶、删除、清空未置顶／确认清空 |
| 发送窗口 | 选择文件、发送、完成 |
| 配对区域 | 添加设备、确认配对、拒绝配对 |

设置页的“应用”、文件“更换”、解除配对等其他按钮不扩展进本次改动。

历史空列表补充说明：“复制文字、图片、文件或文件夹后会出现在这里”。文案沿用当前工作区已有的文件历史能力，不回退功能说明。无搜索结果的空状态保留现有说明。

`arrive` 只接到现有 `emptyState`，不接历史 `ui.List` 行、设备列表或 picker。空状态持续存在时不得因普通重绘反复播放；离开后重新进入可以播放。picker 保留现有一行淡字，不增加大空状态。

尊重系统 `ReduceMotion`，减少动态效果时立即到位。按钮按压和空状态进场期间，页面导航、键盘操作与点击仍立即响应。

### 验证与停手点

- 保留并通过 `TestMainNavigationRemainsImmediateDuringMotion`，覆盖普通动效与 `ReduceMotion`。
- 使用 `ui.NewTester` 显式按下并渲染“复制”按钮，走到 `Pressed()` 路径；松开后原操作只触发一次。使用 fake Board，不操作真实剪贴板。
- 在 `ReduceMotion` 下验证按钮与页面可立即操作，不对 0.97 缩放做像素断言。
- 实机观察历史空列表的短进场和按住“复制”的微缩；列表行和设备行保持稳定。

上述范围通过后停止，不顺带统一其他按钮或调整排版。

## 3. 第二次交付：发送窗口拖放区外观

建议提交标题：`ui: 改善文件拖放区的视觉反馈`。

### 改动位置与行为

视觉补丁只修改 `cmd/snapover/files.go` 的 `filesView` 中 `c.Key("file-drop")` 对应区域。

- 以 `zone.FileDragOver()` 生成 0／1 目标值，通过 `zone.AnimateTo("over", target, ui.Snappy)` 平滑过渡。
- 背景使用 `Surface.Mix(Accent.Alpha(0.08), over)`；边框颜色从普通边框过渡到强调色，线宽从 1 平滑过渡到 2。
- 未选文件时使用 `Draw` 与 `Painter.StrokeDashed` 绘制虚线；选中文件后改为实线。
- 边框在区域内部绘制，照顾圆角与描边边界；绘制自定义边框时避免叠加原有瞬间切换的边框。
- 中文提示、动态文件上限、文件名、大小、选择按钮和禁用状态继续使用现有实现。不给图标加持续弹跳。

**不修改** `DroppedFiles` 的判断与处理分支、`selectFile`、`Validate`、`SendFile`，不放宽单文件限制。拖入多个文件或文件夹时，处理结果与改动前相同。保留传输进度达到 100% 后等待对端确认保存的语义。

本步可等文件剪贴板改动合入后再实施。以后若主动发送支持文件夹，另行修改选择与校验逻辑；本方案不预做这项功能。

### 验证与停手点

- 运行已有 `files_view_test.go`、`files_request_test.go` 所在包的测试，确认发送入口和校验行为保持。
- 实机拖入、移出文件，观察虚线边框与背景平滑变为强调状态；选中后显示实线。
- 检查选择中、发送中仍禁用对应操作，长文件名不破坏现有区域布局。
- Windows 拖放必须单列实机结果，Mac 测试或交叉编译不代替它。

视觉反馈满足上述要求后停止，不调整发送窗口其他布局。

## 4. 第三次交付：历史回写成功 Toast 试点

建议提交标题：`ui: 用原生 Toast 提示历史回写成功`。

### 提示职责

本次仅将主窗口历史操作成功后的“已写回剪贴板”改为 MyGo 原生 `c.Toast()`。其他提示保持现有行为。

| 场景 | 本次处理 |
| --- | --- |
| 主窗口历史正在读取／处理 | 继续 `a.flash` |
| 主窗口历史读取、写回失败 | 继续 `a.flash` |
| 正在接收、同步失败、仅存入对端历史 | 保留 Notice 驱动的现有提示及优先级 |
| 自动同步成功 | 继续安静更新状态，不增加 Toast |
| 主窗口历史实际写回成功 | Toast：“已写回剪贴板” |
| `copy_sync` 失败 | 保留现有系统通知和其他反馈 |
| picker 操作 | 保留 `pickFlash`、目标粘贴及失败反馈，不加 Toast |
| 主动发送成功 | 保留页内“已发送”与“完成”，不加 Toast |
| 清空未置顶、删除、置顶成功 | 本次不新增 Toast，也不做 Undo |

### 最小实现

在 `app` 中增加单条待显示消息，不引入通用通知队列：

```go
pendingToast string

func (a *app) toast(msg string) { a.pendingToast = msg }
```

主窗口 `view` 消费一次后清空：

```go
if a.pendingToast != "" {
	c.Toast(a.pendingToast)
	a.pendingToast = ""
}
```

具体约束：

- 在 `history_paste.go` 的 `completeHistoryPaste` 中，仅主窗口操作且原生 `Publish`／写入返回成功后排入消息。完成读取、加入历史或发送成功都不能触发这条 Toast。
- 成功时结束本次读取的过程提示，避免底栏一直停在“正在读取历史…”；如果期间已被其他 Notice 更新，则保留新提示，不清空同步失败或其他消息。
- 不把 `toast()` 当作跨线程接口。异步结果继续通过现有 `a.update`／UI 调度路径处理，view 中才调用 `c.Toast()`。
- 保留现有取消和失效结果检查。主窗口关闭时清空待显示消息，并沿用现有历史回写取消；旧窗口的结果不得在重开窗口后补弹。
- 不在 picker 或发送窗口消费 `pendingToast`。同一条消息只显示一次，不跨窗口重放。
- 显示时长、数量上限、悬停暂停和读屏沿用 MyGo 默认行为，不增加计时器或自定义 Toast 组件。

### 验证与停手点

- fake Board 写回成功时排入 Toast，主窗口 view 消费后清空；后续重绘不重复显示。
- 读取中和失败仍使用 `flash`；成功不会留下旧的读取提示，也不会清掉期间出现的同步失败等其他提示。
- picker 成功、失败与目标粘贴行为保持，不排入主窗口 Toast。
- 关闭主窗口后异步完成、取消后旧结果返回，以及关闭后重开，都不补弹过期成功提示。
- 保留 `clipboard_result_test.go` 中自动同步成功保持安静、`flash` 与 `displayStatus()` 优先级、旧会话结果无效等语义。
- 使用现有 `history_paste_test.go`、`window_lifecycle_test.go` 的临时目录、fake Board 和窗口生命周期测试方式。

完成“已写回剪贴板”这一条后停止，使用两天再决定是否扩展其他结果提示。

## 5. 三次交付的验证与回退

每一步实现后，在仓库根目录运行：

```sh
go test ./cmd/snapover -count=1
git diff --check
```

只格式化本步修改的 Go 文件。纯文档阶段不要求运行 Go 测试，本文中的测试均为后续实现的验收要求。

每次交付都记录实际通过的测试、实机观察及未覆盖的平台行为。无需为这轮界面细节修改打完整安装包，除非实机验证确实需要产物。

制定方案时，工作区已有大量未提交修改，包括 `window.go`、`ui.go`、`files.go` 和 `history_paste.go`。实施时先确认基线，只暂存本步补丁，不整文件收录已有修改，不重置或覆盖它们。每个提交审阅暂存差异，确保没有协议、依赖或分页变更混入。

三步不互相调用新增的辅助实现：第二步直接用 MyGo API，第三步使用原生 Toast。每个提交通过对应测试后，可通过反向应用该提交独立回退；不要用恢复整个文件的方式回退。后续代码若已改动相同行，按补丁解决冲突并重新验证。

## 6. 本轮明确不做

- 容量条、快捷键提示、设置页组件替换、确认弹窗重做。
- 统一按钮皮肤，或将 `ui.Button` 换成 Solid／Ghost。
- 历史列表、设备列表动效，悬停 Lift，音效和持续装饰动画。
- 替换图片／文本预览、系统托盘或权限入口。
- 文件／文件夹协议、接收确认、剪贴板保护、存储格式和限制调整。
- 删除撤销、通用 Toast 队列，或批量替换 `a.flash`。

本轮验收聚焦：历史空列表进场、按钮按压、拖放区反馈，以及主窗口历史写回成功的一条 Toast。
