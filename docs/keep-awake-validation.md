# Windows 保持唤醒验证

在「设置 → 保持唤醒」开启「防止自动锁屏」。此功能默认关闭，开关状态保存在本机，重新启动后沿用。关闭主窗口后继续随托盘运行。

实现通过专用线程调用 `SetThreadExecutionState`，保持系统和显示器唤醒；空闲约 60 秒后，通过 `SendInput` 发送零位移的相对鼠标事件，尝试重置屏保计时。每次尝试至少间隔 60 秒，不发送按键、点击或滚轮事件。系统明确禁止模拟输入重置屏保计时时，不启用这项功能。

后台约每 5 秒检查会话和交互桌面。手动锁屏、切换用户、断开远程桌面或进入安全桌面时暂停并释放电源请求，返回后恢复。主动睡眠、合盖等行为仍由 Windows 管理。关闭开关或退出软件时等待后台线程释放请求。系统调用失败时停止后台工作，设置页显示原因；修复原因后关闭再开启开关重试，错误也会写入 `logs/snapover.log`。

关闭开关时先停止后台，再保存关闭状态。即使保存失败，本次运行也保持停用，并提示下次启动可能重新开启。远程桌面会话查询服务不可用时，只有确认进程属于当前物理控制台会话才允许继续，并仍需通过交互桌面检查；权限错误等其他查询失败不会走此回退。

## 在同一台 Windows 上对照验证

1. 固定电源状态、合盖状态、外接显示器和前台应用，关闭其他防休眠工具。先关闭本功能，不操作电脑，记录实际发生熄屏、待机、锁屏的时间。无法复现时，暂不能判定后面的测试有效。
2. 在相同条件下开启本功能，确认设置页没有报错。等待超过第一步测得的时间，建议观察至少 30 分钟，检查是否仍发生熄屏、待机或锁屏。
3. 关闭主窗口，确认托盘仍在，再等待一个原来的锁屏周期，确认功能不依赖主窗口。
4. 保持开关开启，按 `Win+L`，确认能正常锁屏、不会自行解锁；解锁后检查功能恢复。另行验证主动睡眠和唤醒。
5. 关闭本功能，在相同条件下等待，确认原来的自动熄屏、待机或锁屏行为恢复。开启后退出整个 Snapover，再确认一次恢复行为。
6. 电池供电和接通电源分别验证，避免把不同电源方案的结果混在一起。

`GetLastInputInfo` 时间更新只说明当前会话记录到了输入，不能代替上述验证。如果记录日志，应对齐显示器状态、会话锁定/解锁和待机事件的时间，不应只凭 506/507 事件推断锁屏原因。

## 验证范围

自动化测试覆盖空闲输入、锁定暂停与恢复、策略变化、取消和失败后的电源请求释放，以及配置默认值与保存。Windows 交叉编译只能检查编译和链接，无法证明目标机器的域策略或 Modern Standby 行为。实际机器上的对照验证尚需完成。

实现依据：[SetThreadExecutionState](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setthreadexecutionstate)、[屏保计时与模拟输入限制](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-systemparametersinfow)、[GetLastInputInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getlastinputinfo)。
