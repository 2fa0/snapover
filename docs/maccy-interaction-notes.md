# Maccy 调研与交互借鉴笔记

日期：2026-10-29  
状态：第一、第二批已实现于 Snapover 0.8.0；本轮代码审计与回归修复已完成，双平台输入法及跨应用粘贴仍待实机验收。

本文保留借鉴 Maccy 的产品判断，并以当前代码说明已实现行为、边界与后续方向。版本更新摘要见 [更新记录](CHANGELOG.md#080)。

## 1. 当前结论

值得吸收的是把常用动作留在快速历史里、让搜索结果解释命中原因，以及让常用条目的选取更快。
Snapover 还承担跨设备同步，不需要复制 Maccy 的整个功能和技术栈。

| 方向 | 0.8.0 状态 | 边界 |
| --- | --- | --- |
| 快速历史里的只复制、置顶和删除 | 已实现 | Enter／双击仍直接粘贴；文件历史不恢复正文 |
| 动作和快捷键可发现 | 已实现右键菜单 | 不采用打开若干次后永久消失的提示 |
| 搜索命中展示 | 已实现片段与高亮 | 正文命中显示附近片段；来源等字段命中时保留原摘要，另显示命中说明 |
| 置顶项固定键位 | 已实现最多 9 条 | 仅在快速历史打开时生效，不注册每条记录的系统全局热键 |
| 忽略下一次复制 | 已实现托盘入口和取消 | 该次本机复制不记录、不同步；不等同于暂停同步 |
| 应用排除、自定义排除类型 | 未实施 | 来源展示信息不能直接当作可靠的应用身份过滤条件 |
| OCR、片段编辑、全局片段热键 | 后排 | 分别评估跨平台成本、数据语义和快捷键冲突 |

## 2. Maccy 参考依据与事实修正

本次参照版本为 [Maccy 2.8.0](https://github.com/p0deje/Maccy/releases/tag/2.8.0)，
官网为 [maccy.app](https://maccy.app)，源码采用 MIT 许可证。该版本要求 macOS 14 及以上。
Stars、下载量和商店价格不作为本项目的功能决策依据，本文不维护这些易变化的统计。

### 2.1 可以确认的交互

[官方操作说明](https://github.com/p0deje/Maccy#usage) 列出了搜索、复制、粘贴、删除、置顶及忽略下一次复制。
文档示例以 Enter 复制、Option+Enter 粘贴区分动作；实际行为也受偏好设置影响，不能据此推断作者的设计动机。

Maccy 的置顶项固定选取键位属于弹窗内操作，不能理解成“无需打开窗口的系统全局热键”。
可参照 [KeyShortcut.swift](https://github.com/p0deje/Maccy/blob/2.8.0/Maccy/KeyShortcut.swift)。

Maccy 的搜索实现携带命中范围，并支持精确、模糊、正则和混合模式。
Snapover 先借鉴命中展示，尚未增加新的搜索模式。
参考 [Search.swift](https://github.com/p0deje/Maccy/blob/2.8.0/Maccy/Search.swift) 与
[HistoryItemDecorator.swift](https://github.com/p0deje/Maccy/blob/2.8.0/Maccy/Observables/HistoryItemDecorator.swift)。

### 2.2 不再沿用的比较结论

- **不再说我们的敏感类型清单“更完整”。** Snapover 覆盖 macOS 通用敏感标记和 Windows 标记；Maccy 另有部分 Mac 应用私有类型，两者覆盖面不同。
- **不再只用 tooltip 比较预览。** Maccy 已有侧滑预览、图片 OCR 复制和置顶内容编辑；Snapover 有代码文本、原图和文件夹树预览，各有侧重。见 [版本记录](https://github.com/p0deje/Maccy/releases)。
- **不再说 Maccy 代码“没有任何网络路径”。** 历史保存在本机不等于整个应用不使用网络，自动更新等功能须另行区分。
- **不再说 Snapover 不是轮询模型。** 当前每 50 ms 检查剪贴板序号，连续变化稳定 150 ms 后读取，并校验读取前后的序号。要保护的是稳定等待、序号校验与防回环，轮询本身不是正确性问题。
- **不把“零配置”“修饰键一致”等产品判断写成绝对事实。** Snapover 本地历史可独立于配对使用，跨设备同步仍需要明确配对与权限。

## 3. 0.8.0 已实现的动作

### 3.1 快速历史操作与右键菜单

| 动作 | macOS | Windows | 结果 |
| --- | --- | --- | --- |
| 粘贴 | Enter／双击 | Enter／双击 | 写回剪贴板、关闭弹窗、尝试向原目标投递粘贴 |
| 只复制 | Option+Enter | Alt+Enter | 写回剪贴板并关闭弹窗，不投递粘贴按键 |
| 置顶／取消置顶 | Command+Shift+P | Ctrl+Shift+P | 保留搜索词，保持选中该记录 |
| 删除 | Command+Shift+Backspace | Ctrl+Shift+Backspace | 保留搜索词，选中相邻记录 |
| 使用固定置顶项 | Command+1–9 | Ctrl+1–9 | 直接粘贴键位对应的置顶记录 |

菜单提供相同动作和快捷键提示。普通 Backspace 继续编辑搜索词，没有采用会与删词冲突的 Option+Backspace。
文件和文件夹历史只保存名称、目录摘要，菜单禁用复制／粘贴并说明需重新复制；仍可置顶、删除。

历史读取和图片准备复用已有后台流程。清理或其他历史变更进行中会拒绝重复操作；关闭窗口、删除源记录或取消请求后，不发布过期的粘贴结果。
“只复制”使用同一准备流程，但不会调用原目标的粘贴投递；等待文案也区分复制与粘贴。

整理后的选择恢复遵守用户最新意图：若操作期间修改了搜索词，以新查询的选择为准，不恢复旧查询的记录或行号。
复制历史原有排序继续保留，本次没有增加拖动排序和内容编辑。

### 3.2 搜索片段与命中高亮

- 正文命中时显示附近短片段，最多保留 160 个字符，首尾按需加省略号；匹配采用现有大小写不敏感规则。
- 来源应用、来源设备、文件名、目录项等字段命中时，保留原内容摘要，另显示字段名、命中片段和高亮，避免同一来源的多条记录看起来完全相同。
- 主历史页与快速历史共享展示规则；命中片段最多显示两行，适配窄窗口和深浅主题。
- 片段内每一处关键字都标出，不只第一处；一处片段最多标 24 处，避免单字查询把整段都涂满。
- 命中样式为加粗加浅色底块，底块随主题取 `Selection`；加粗让标记不只依赖颜色。选中的行是强调色填充，底块在那里几乎看不见，因此改为关键字保持原亮度、周围文字降到 78% 透明度，靠明暗对比区分。
- 快速历史搜索时搜索框右侧显示结果条数，正文仍在后台读取时显示「搜索中…」。
- 已加载字段（摘要、来源、设备、文件名、目录项、类型）的命中先同步给出，后台正文搜索结果到达后整体替换，不在读取期间清空列表；正文独有的命中仍由后台结果补上。
- `MatchText`、`MatchField`、`MatchRanges` 只用于展示，使用 `json:"-"` 排除持久化；复制、粘贴仍使用完整原文。

这比仅在旧标题上切分高亮多一步：命中可能在外置正文深处，必须由搜索层提供实际片段。

长文本继续后台分块读取。更换搜索词、刷新历史或关闭发起窗口会取消旧请求，每个视图保留一个搜索工作队列。

### 3.3 置顶项固定键位

可粘贴的文本、图片置顶项自动分配空闲的 1–9 键位。键位显示在快速历史行尾，仅在该窗口内生效。

- 键位保存在历史记录的可选 `pin_key` 字段中，随快照与变更日志恢复，不写入设置或配对记录。
- 绑定记录 ID，不按当前行号、搜索结果顺序或最新复制顺序计算。
- 取消置顶或删除会释放键位，其他已分配记录保持原键位。
- 超过 9 条仍可置顶，但没有数字快捷键。未分配的旧置顶记录会在启动时获得剩余空位，不挤占已有绑定。
- 文件名称历史不分配粘贴键位。
- 旧历史升级时通过已有 `pin` 日志操作补充分配；写入失败回滚对应内存变更。新字段对旧版 JSON 读取兼容，但降级后被旧版重写的数据不保证保留键位。

### 3.4 忽略下一次复制

托盘菜单提供“忽略下一次复制（不记录、不同步）”，等待期间可再次点击取消。

| 行为 | 本机历史 | 剪贴板同步 |
| --- | --- | --- |
| 暂停同步 | 继续记录本机复制 | 暂停剪贴板收发 |
| 忽略下一次复制 | 该次不记录 | 该次不发送 |

“下一次”指启用之后新的、经过稳定等待的本机复制事件。它不修改系统剪贴板，不追溯清理已有历史，也不跨重启保存。
启用前已在处理队列里的事件仍按原规则处理；稳定等待合并连续写入的语义不变。

实现边界：

- 在进入本地处理队列前判定，队列已满也不会把这次忽略错误地留给后续复制。
- 记录已忽略的序号，避免同一事件重复投递后又进入历史或发送队列。
- 远端回声不消耗忽略；历史回写使用独立的本进程标记识别，但仍保留既有的历史回写记录／同步行为。
- 标记检查结合读取后的序号校验，不能仅凭“写完后再读一个序号”认领系统剪贴板。
- 忽略的本机复制仍更新本机优先保护时间；若它对应“复制并同步”请求，明确返回未发送，不报告成功。
- 不改变正常接收、主动发送文件和 CLI 显式发送的规则；不是暂停同步或通用隐私模式的替代品。
- 标记与内容读取仍可能发生，“不记录”不代表完全不读取系统剪贴板；正文和图片字节不写入运行日志。

## 4. 本轮代码审计与修复

审计范围为 0.8.0 这两批改动及其直接调用路径，没有扩展到全项目重构。

| 问题 | 影响 | 修复与回归覆盖 |
| --- | --- | --- |
| 来源等字段的命中片段替换原摘要 | 同一应用的多条短文本无法从列表区分 | 保留摘要、另列命中说明；`TestSourceSearchKeepsDistinctContentsVisible` 覆盖两个历史视图，排除辅助功能标签造成的假通过 |
| 整理期间修改查询，完成后仍恢复旧选择 | 新查询选中项被旧操作覆盖 | 输入变化取消旧选择恢复，但继续显示操作完成结果；`TestPickerNewQuerySupersedesPendingSelectionRestore` 覆盖 |
| 等待搜索完成时每 1 ms 请求刷新 | 异步搜索期间产生不必要的界面刷新 | 仅在实际恢复选择后请求下一帧；等待仍使用原有搜索轮询节奏 |

同时核对了忽略动作的事件边界、远端回声和历史回贴排除、发送确认、固定键位的日志／快照恢复、旧历史分配及失败回滚。
自动化验证不能替代真实系统剪贴板竞争、输入法和目标应用行为的实机验收。

- 280 像素宽快速历史的深浅主题离屏渲染检查。
- 本轮新增的来源搜索及查询／异步整理冲突回归测试；均先复现失败，再验证修复。

本轮审计修复后重新执行了全量测试、上述相关包的 race 检查、`go vet`、macOS 窗口测试、Windows 主程序测试二进制交叉编译及窄窗口深浅主题离屏检查，均通过。Windows 剪贴板包测试二进制在首轮实现完成后交叉编译通过，本轮未修改该包。

仍需实机覆盖：macOS 中文输入法与非美式键盘、Windows IME、原生右键菜单、辅助功能权限、真实跨应用粘贴，以及开启忽略时与其他剪贴板工具竞争的行为。
`ui.NewTester` 能验证收到事件后的处理，不能证明操作系统和输入法一定交付同样的按键。
Windows 交叉编译只证明可以编译；macOS 窗口测试也不等于真实目标程序粘贴验收。

## 6. 保留的产品取舍与后续方向

### 本次不增加的功能

- **纯文本粘贴模式**：当前不保存富文本，无须增加一个与普通文本粘贴相同的动作。
- **存储或监测架构迁移**：保留 JSON 快照、变更日志、外置正文，以及轮询、稳定等待、序号校验和防回环。
- **限次后消失的快捷键提示**：打开次数不代表已经学会，采用长期可查的右键菜单。
- **托盘修饰键手势**：已提供明确菜单入口，不以跨平台手势支持作为功能前提。

### 后续按需求评估

1. **按应用排除、自定义类型**：先确认稳定的应用身份与复制来源，不能直接用展示名或事后取得的前台应用名承诺可靠排除。没有证据证明 Windows 的成本必然高于 macOS。
2. **OCR**：优先本地识别，明确开关、后台任务、索引与解码上限，再评估 Windows／macOS 两套实现。不因增加搜索能力而改变原图片或同步载荷。
3. **片段编辑**：先区分“当时复制过的历史”与“用户维护的常用片段”，避免悄悄改变历史原文。
4. **全局片段热键、拖动排序**：有明确高频需求后再增加配置、冲突处理与持久化语义。

快速历史不承担连接管理，但应保留内容来自本机还是同步、来源设备，以及当前操作失败的说明。
配对、重连和网络配置继续在设备与设置页处理，不能用“永远不显示设备名或错误”来删掉与当前选择有关的信息。
