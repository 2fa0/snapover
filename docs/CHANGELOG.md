# 更新记录

## 0.5.3

- 确认企业微信中截图无法直接 Ctrl+V 的原因是 RDP 剪贴板同步覆盖了 Snapover 写入的内容；关闭远程桌面连接的剪贴板共享／重定向后恢复正常，README 已补充说明。
- 移除排查期间增加的 Windows 剪贴板所有者检测、临时兼容逻辑、采集工具及其测试，恢复原有同步标记机制。
- 保留 Windows 位图头完整初始化的修复及回归测试。

## 0.5.2

所有者识别方案已在 0.5.3 撤回。位图头初始化修复仍然有效。

- Windows 远端图片与历史回贴统一使用 PNG 和 CF_DIB 格式，不再附加自定义同步标记；通过系统剪贴板所有者和序号识别远端图片，避免重复同步，同时保留历史回贴后的同步行为。
- 修复 Windows 剪贴板位图头未完整初始化的问题，确保压缩类型和调色板等字段不残留原生内存中的随机值。
- 新增原生写入识别与非零内存场景的回归测试。企业微信 Ctrl+V 的结论见 0.5.3。

## 0.5.1

- Windows 剪贴板暂时被占用时，在后台短暂等待并重试写入；重试期间若本地复制了新内容、暂停同步或连接已改变，则停止写入。
- 剪贴板写入失败时，收到的文字或图片仍保留在对端历史中，并向发送端报告实际结果。
- 同步失败、发送队列满或断线重连后，可以重新复制同一内容发送，避免被内容去重永久拦截。
- 普通日志记录剪贴板入队及对端处理结果，便于定位传输、剪贴板写入和历史保存问题；日志不包含复制的正文或图片数据。
- macOS 文件右键入口改为「服务 → Snapover 发送文件」，直接复用 Snapover 后台；启动时移除旧的 Automator 快速操作，避免继续产生 WorkflowServiceRunner。

## 0.5.0

这次更新集中补齐日常使用中的快捷入口、历史空间管理和同步结果反馈。

- **自定义快速历史快捷键**：可在设置中更换组合、恢复默认。组合被占用或设置保存失败时，保留原有快捷键。
- **历史容量管理**：默认内容上限 2 GB，可调整上限、刷新占用、清理全部未置顶记录。文本、原图、缩略图和预览均计入容量；超限先清最旧记录，置顶始终保留。删除失败会显示原因，残留文件会在下次维护时重试。
- **自动同步确认**：按条等待对端写入结果，正常成功保持安静，失败、超时和未确认断线显示原因；过期但尚未发送的内容不会在之后补发。
- **同时复制保留历史**：本地刚复制过时，收到的远端内容只存历史，不覆盖当前剪贴板。发送方收到单独的“已保存历史”结果；CLI 仍只把实际写入剪贴板视为成功。
- **移除远程桌面保活**：实机日志确认模拟鼠标无法可靠重置 RDP 空闲计时，已移除设置入口、后台输入模拟和专用诊断。
- **MyGo 更新**：依赖及构建工具从 v0.4.8 升级到 [v0.5.1](https://github.com/egoist/mygo/releases/tag/v0.5.1)。
