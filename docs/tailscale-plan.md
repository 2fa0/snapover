# Tailscale 支持实施计划

状态：首版代码和自动化验证已完成，真实 Tailscale 双机验收待具备环境时执行。

已完成默认关闭的设置、手动地址入口、双地址兼容存储、按设备身份重连、广播候选更新、路径诊断及发送目标绑定。以下保留实施设计和实机验收清单，实际操作见 README 的“通过 Tailscale 跨网络连接”。

实际验证：`go test ./...`、`go vet ./...`、`go test -race ./internal/lan ./internal/settings ./internal/sync` 均通过；`internal/lan`、`internal/settings`、`internal/sync`、GUI 和 CLI 的 Windows amd64 测试二进制交叉编译通过，产物位于临时目录并已清理。

环境限制：本机未发现可用的 Tailscale IPv4 隧道，也没有 Windows 对端。第 2 节的真实跨网 TCP 验证和第 9 节的双机验收尚未执行；现有覆盖使用接口地址策略测试、可控拨号/退避测试及真实 TLS/配对/会话的内存通道测试，不等同于平台实测，也未验证 macOS 各 Tailscale 安装版本及中继链路表现。

目标：用户自行安装并连接 Tailscale 后，可以通过 Tailscale IPv4 添加设备，继续使用原有配对、剪贴板同步和发送功能；局域网地址与 Tailscale 地址独立保存，断线后自动尝试可用路径。

本计划对应完整可用首版，估计 3–5 人日，包含针对性测试和具备环境时的 Mac / Windows 双机验证。此前 1–2 人日的估计仅对应手动连接的基础版本。

## 1. 首版范围和用户操作

- 设置增加“允许通过 Tailscale 连接”，默认关闭，两端均需开启。旧用户升级后的连接行为保持原样。
- “通过地址连接”提供局域网 / Tailscale 两种方式。Tailscale 方式接受 `100.64.0.0/10` 内的 IPv4，端口默认 47821，可使用自定义端口；不把整个 `100.*` 当作有效范围。
- 首次连接仍在两端点击“添加设备”，核对校验码并分别确认。已有设备的详情提供添加、修改和删除 Tailscale 地址的入口，修改后连接验证目标设备身份，通过后保存。
- 同一设备只显示一条配对记录；详情分别显示局域网地址、Tailscale 地址和当前使用的连接方式。删除一个地址不解除配对；解除配对则清除该设备的全部地址并取消重连。
- 保留现有局域网自动发现。跨网设备由手动地址添加。
- 首版不新增 MagicDNS / Tailscale IPv6 支持、Tailscale 设备自动枚举、安装或登录管理、子网路由适配、内嵌 Tailscale SDK、连接测速或主动择优切换。原有局域网地址输入能力保持。

## 2. 先验证两端实际网络行为

在写正式功能前完成一轮最小网络验证，记录 Mac 和 Windows 上的本机地址、出站连接源地址、接入连接本地地址与对端地址。只记录网络元数据，不读取剪贴板和真实身份目录。

- 使用独立临时 TCP 测试程序，确认系统 Tailscale 已连接时，两端能用 Tailscale IPv4 建立普通 TCP 连接。
- 核对 Go 的网卡枚举与 TCP 实际地址是否一致，覆盖 macOS 独立安装版和 Windows；如要声明支持 Mac App Store 版，也需验证该版本。
- 验证 Tailscale 关闭、其他 VPN 同时启用以及换网后的表现。
- 产出明确的连接分类规则及平台支持记录。若某版本无法提供可辨认的本地 Tailscale 地址，不退化为允许所有 utun / 虚拟网卡；单独定位该版本的实现差异。

## 3. 收发连接策略

涉及 `internal/lan/lan.go`、`internal/sync/node.go`、`internal/settings/settings.go` 及对应测试。

- 将“是否为虚拟网卡”和“是否允许这条连接”分开判断。保留现有虚拟网卡分类，Tailscale 不加入局域网广播接口。
- 开关关闭时，维持原有物理网卡拨号和虚拟接口接入限制。
- 开关开启且用户选择 Tailscale 路径时，要求目标为允许的 IPv4 范围，并存在匹配的本地隧道地址；使用该地址拨号，不能继续绑定物理网卡，也不能在缺少隧道时静默改走其他路径。
- 接入判断同时使用本地地址、远端地址和设置，仅对符合已验证 Tailscale 路径规则的连接增加例外。其他 VPN 的处理保持原状。路径判断失败时给出具体原因。
- `100.64.0.0/10` 是共享地址空间，不作为设备身份或安装了 Tailscale 的证明。端点类型由明确选择及连接上下文确定，设备信任仍由原有 TLS 和配对流程决定。
- 连接、测试连接和诊断共用同一套路径判断，避免“测试连接”走另一张网卡。
- 热切换设置通过同步或原子状态供网络线程读取。关闭开关立即禁止新的 Tailscale 连接，取消相关拨号并关闭现有 Tailscale 会话；已有局域网连接保持。已选设备有局域网地址时按重连策略恢复，无地址时显示离线原因。
- 如果用户通过 `-listen` 限定监听地址，不擅自扩大监听范围，提示需要监听 Tailscale 地址或通配地址。

## 4. 地址保存和旧数据兼容

涉及 `internal/sync/peers.go`、`internal/sync/engine.go` 及对应测试。

- 保留现有 `addr` 字段供兼容使用，增加可选的 `lan_addr` 和 `tailscale_addr`。每类保存一个已验证地址，不引入无限地址列表。
- 新版按分类字段连接；旧记录只有 `addr` 时继续作为原有连接地址使用，不因一次读取就改写磁盘，不因为地址位于共享范围就自动认定它是 Tailscale。
- 成功完成身份验证与配对后，按实际路径更新对应字段，同时更新兼容字段 `addr` 为本次成功连接地址。局域网连接不覆盖 `tailscale_addr`，Tailscale 连接不覆盖 `lan_addr`。
- mDNS、用户输入和“测试端口成功”均不能直接覆盖已验证地址。已有设备修改地址时，验证其设备 ID 和证书指纹后才能保存；失败保留原地址。
- 接入连接继续使用来源 IP 和对端声明且经过范围验证的监听端口，不能保存临时 TCP 来源端口。
- 继续沿用临时文件替换与失败回滚，不改变身份、信任时间及解除配对语义。协议格式和协议版本不因本功能调整。
- 降级到旧版本时，旧版本仍可读取配对记录，但不能使用新增的 Tailscale 能力，且旧版本重新保存后可能丢失新增字段。README 明确说明不保证降级后保留双地址；不承诺无损往返兼容。

## 5. 按设备重连，地址作为候选路径

涉及 `internal/sync/node.go`、`cmd/snapover/window.go`、`cmd/snapover/devices.go` 和配对测试。

- 已配对设备始终以设备 ID 为重连目标，每次连接都携带预期 ID；首次添加尚未识别设备时，只尝试用户输入的一个地址。
- 已配对设备自动重连时，顺序为：当前发现的局域网地址、已保存的局域网地址、已保存的 Tailscale 地址，去重后最多三个候选。没有分类保存的局域网地址时，未分类旧地址占用第二个位置，仍按原有路径处理。
- 用户显式选择某个地址连接时，先尝试该地址；失败后再尝试同一已配对设备的其余候选。未配对设备不进行候选扩展。
- 保留现有 `-peer` 启动参数的优先级；地址匹配已保存的分类记录时沿用对应路径，否则仍按原有方式处理。首版通过 GUI 添加新的 Tailscale 地址，不新增 CLI 配对或连接参数。
- 每轮顺序尝试，沿用现有 TCP 5 秒与 TLS 10 秒上限；本轮失败后按 1、2、4 秒退避，最长 30 秒。拨号使用 `DialContext`，TLS 握手及会话建立同样响应上下文取消，切设备和退出不等待旧轮次自然超时。
- mDNS 更新只替换候选，不反复取消正在进行的 Tailscale 拨号；重复快照不重置尝试顺序和退避。新候选在下一次尝试或下一轮生效。
- 已建立的连接保持，局域网重新出现时不主动断开稳定的 Tailscale 会话；下次断线再按优先级选择。
- 仍只保留一个活动会话，复用两端同时拨号时已有的确定性竞争规则。
- 地址指向错误设备或证书不匹配时，拒绝并隔离该候选直到用户重新尝试或地址更新；其他已保存路径仍可验证。配对拒绝、取消、超时或解除配对时终止对应连接流程，不自动重新发起首次配对。
- 所有异步结果携带目标设备和轮次标识，旧结果不能恢复已取消的拨号或覆盖新的界面状态。

## 6. 界面、诊断和发送入口

涉及 `cmd/snapover/devices.go`、`window.go`、`segments.go`、`main.go`、`files_request.go`，以及实际涉及的设置视图、后台发送处理和测试。

- 新开关说明：需要两端自行安装并连接 Tailscale，同时允许设备间访问 Snapover 的监听端口；不会自动安装或配置 Tailscale。
- 连接状态可显示“通过局域网连接”或“通过 Tailscale 连接”。这是 Snapover 的访问路径，不宣称已辨认 Tailscale 内部直连或中继。
- 广播网段里仍不勾选 Tailscale；说明改为“仅用于地址连接，不参与局域网发现”。其他虚拟网卡提示保持原样。
- 错误区分：未开启支持、缺少可用隧道地址、TCP 连接失败、TLS / 身份验证失败、等待双方配对确认。不能仅凭 TCP 超时就断言是防火墙或 Tailscale 权限错误。
- 冷启动文件发送目前通过单个地址查找目标设备，改为传递或解析稳定的目标设备 ID。两条地址都属于同一目标设备；地址回退不算切设备。
- CLI 继续复用本机后台连接，本机控制服务仍只监听回环地址。核对 GUI、CLI、Finder / Windows 发送入口在断线、路径变化、设备切换时仍遵守原有确认和失败语义，不把发送中内容自动重发给其他设备。
- 更新 README 的支持范围、启用步骤、端口要求、双地址与重连规则、降级限制及排查说明。根据本工作区已有变更核对当前发送能力，不把它改回旧的功能范围。

## 7. 分步交付与检查

1. **验证跨网 TCP 和平台地址表现（约 0.5 日）**：输出两端测试结果、路径识别规则及已验证版本。
2. **打通受控 Tailscale 连接（约 0.5–1 日）**：增加默认关闭的设置和路径判断，证明开启后能连接、关闭后行为与之前一致。
3. **保存双地址并完成重连（约 1–1.5 日）**：旧记录可加载，两类地址不互相覆盖，候选重试可取消且不被广播反复打断。
4. **接入设备页面和所有发送入口（约 0.5–1 日）**：可为现有设备维护 Tailscale 地址，界面说明准确，文件目标按身份绑定。
5. **完成回归、双机验收和文档（约 0.5–1 日）**：给出通过项、失败项及未覆盖平台，只有需要安装产物时才打包。

实现时以当时工作区为准，保留其他未提交修改，不升级依赖、不更改版本号、不重写剪贴板和文件协议。若缺少 Windows 或某个 Tailscale 版本的实机环境，交付中单列未验证项，不能用交叉编译替代。

## 8. 自动化验证

扩展已有临时目录、假剪贴板和 UI tester 测试；路由、时序和拨号失败通过可注入的最小测试接缝验证，不依赖真实 Tailscale 或真实网络。

- 路径：开关关闭仍排除 Tailscale；开启后只允许指定路径；无隧道不回退物理网卡；其他 VPN、物理 CGNAT 地址和重叠网段不被简单范围判断误放行；自定义监听地址仍受尊重。
- 存储：旧记录加载、双地址独立更新、重启恢复、错误设备不保存、磁盘保存失败回滚、解除配对清理、兼容字段行为。
- 重连：局域网失败后走 Tailscale、候选去重、上限和退避、重复 mDNS 不打断、旧轮次结果失效、切设备取消、已连接不抢占、两端同时拨号只留一条连接。
- 设置：关闭后取消拨号并断开相应会话，禁用期间不再重试；局域网会话不受影响；保存设置失败时行为不改变。
- 安全：首次仍要求双方确认；超时、拒绝、指纹变化和目标身份不符继续被拒绝；撤销后不能被旧连接重新恢复。
- 发送：冷启动仍定位同一设备；同一设备路径回退可重连；切换另一设备不能误发；中途断线按现有语义报告失败，不虚报成功。

## 9. 实机验收与完成条件

使用隔离测试数据目录、明确准备的测试文本、图片和文件，不复制真实身份目录，不清空真实历史。

| 场景 | 通过条件 |
| --- | --- |
| 两台设备在不同网络，仅通过 Tailscale 可达 | 手填地址后完成双向确认，文字、图片和当前支持的发送操作成功，实际接收结果准确 |
| 同时具备局域网与 Tailscale | 自动重连优先尝试局域网，两类地址分别保存；当前稳定会话不被抢占 |
| 从同一 Wi-Fi 切到不同网络 | 已保存 Tailscale 地址可自动恢复同一设备连接，无需重新配对 |
| Tailscale 断开、恢复 | 显示准确原因并按退避重试，恢复后重新连接，不持续刷屏 |
| 双端重启、休眠唤醒 | 配对及双地址保留，恢复后可连接，无重复活动会话 |
| 关闭支持开关 | 相关连接和拨号结束，局域网继续可用，Tailscale 地址保留供下次开启 |
| 错误设备或指纹变化 | 拒绝连接，不覆盖已保存的可信地址 |
| 发送过程中断网或切换设备 | 不误发、不自动重发、不虚报接收成功 |
| 慢速或中继链路 | 验证图片、文件和心跳超时；仅在出现实测失败时调整相关超时并补回归 |
| 与其他 VPN 同时运行 | 原有非 Tailscale 路径限制和局域网发现行为无回归 |

完成条件：上述代码范围完成、相关自动检查通过、Mac / Windows 双机验收有记录、README 与行为一致；环境未覆盖项明确列出。首版不要求自动枚举设备或主动切换最佳路径。
