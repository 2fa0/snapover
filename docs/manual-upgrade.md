# 手动升级 Snapover

最新安装包在公开发布页：<https://github.com/2fa0/snapover/releases/latest>

配对记录、复制历史和设置都在数据目录里，不在程序文件里。按下面替换程序即可，不要拷贝 `identity/`，也不要覆盖数据目录。

数据目录：

- macOS：`~/Library/Application Support/Snapover`
- Windows：`%AppData%\Snapover`
- 便携版：安装目录旁的 `data/`（有 `portable.flag` 时）

升级后不要回退旧版：新版写出的历史或设置，旧版可能读不了。

## 先判断要不要手动装

打开 Snapover，看设置 → 关于与更新里的当前版本。也可以点「检查更新」，或从托盘菜单点「检查更新…」。

下面几种情况需要手动安装一次：

- 还没有内置更新器的旧版（0.8.0 之前）
- 更新地址换过仓库。0.8.4 起改到 `2fa0/snapover`，更早的安装包仍会去旧地址检查，必须手动装一次 0.8.4 或更新版本
- 设置页提示这个版本不能自动更新：从磁盘映像直接运行、装在不可写目录，或用 `go run` / `go build` 跑的开发版
- 自动更新失败，或你想一次换到指定版本

手动装好、并且程序不在只读位置之后，以后就可以继续用应用内更新。

## 选哪个文件

发布页会列出很多附件。**手动安装只用安装包**，不要下更新器用的 `.tar.gz`、`.delta` 或 `update-*.json`。

| 电脑 | 下载 |
| --- | --- |
| Apple 芯片 Mac（M 系列） | `snapover-<版本>-arm64.dmg` |
| Intel Mac | `snapover-<版本>-amd64.dmg` |
| Windows 10/11 x64 | `Snapover-<版本>-windows11-x64.zip`，或 `snapover-<版本>-windows-amd64.tar.gz` |

不确定 Mac 是哪一种：左上角苹果菜单 → 关于本机。芯片一栏写 Apple 就下 arm64，写 Intel 就下 amd64。

Windows 没有安装器。ZIP 解压后是完整程序目录，适合第一次安装或整夹替换。`.tar.gz` 是自动更新用的归档，里面同样有 `Snapover.exe`，也可以解压覆盖，但日常手动升级优先用 ZIP。

## Mac：用 DMG 替换应用

1. 完全退出 Snapover：点菜单栏图标 → 退出。不要只关窗口。活动监视器里也不该再看到 Snapover。
2. 打开下载的 `.dmg`。不要把里面的应用直接留在磁盘映像里运行，那样不能自动更新，权限也可能不稳定。
3. 把 `Snapover` 拖进「应用程序」。系统问是否替换时选替换。
4. 推出磁盘映像。
5. 第一次在这台 Mac 上打开这个包时，可能被 Gatekeeper 拦住。当前包是 ad-hoc 签名，别的 Mac 上很常见：
   - 打开时如果提示「无法验证开发者」，到系统设置 → 隐私与安全性，在被拦提示旁点「仍要打开」。
   - 或者按住 Control 点应用程序里的 Snapover，选打开，再确认。
6. 启动后打开设置 → 关于与更新，确认版本号已经是刚装的版本。

更新只替换 `/Applications/Snapover.app`。配对、历史、接收文件夹路径和快捷键都还在数据目录里。

### 更新后重新允许权限

ad-hoc 签名每次换程序后，系统可能把辅助功能和本地网络当成新应用。快捷粘贴失败、发现不到局域网设备时，按下面再允许一次：

- 系统设置 → 隐私与安全性 → 辅助功能：找到 Snapover，打开开关。没有这一项就先用一次快速历史快捷键，等系统弹窗。
- 系统设置 → 隐私与安全性 → 本地网络：打开 Snapover。macOS 15 及以上更常需要这一步。

开机启动如果失效，到设置里重新打开「开机启动」，或到系统设置 → 通用 → 登录项里允许 Snapover。

Finder「服务 → Snapover 发送文件」一般会随新版 Info.plist 重新登记。菜单里没有时，到系统设置 → 键盘 → 键盘快捷键 → 服务里检查是否勾选。

拿到 Developer ID 并公证之后，这些授权会随签名保留，不必每次重开。

## Windows：替换程序目录

1. 完全退出 Snapover：托盘图标 → 退出。任务管理器里也不该再看到 `Snapover.exe`。
2. 记下现在的安装位置。常见是自己解压出来的文件夹，例如 `C:\Apps\Snapover`。便携版看这个目录里有没有 `portable.flag`。
3. 解压新的 ZIP。里面应有 `Snapover.exe`，旁边通常还有 `snapover-cli.exe`、`app.png`、`bird.png`。把这些文件拷进原来的安装目录，覆盖旧文件。
4. 不要删：
   - 同目录的 `portable.flag`、`data/`
   - 你自己放进去的其他文件
   - `%AppData%\Snapover`（非便携版的数据目录）
5. 再运行 `Snapover.exe`。打开设置 → 关于与更新，确认版本号。

Windows 目前没有代码签名，SmartScreen 可能提示「Windows 已保护你的电脑」。点「更多信息」→「仍要运行」。

如果以前是从磁盘映像、只读网盘或受保护目录运行，请先拷到自己能写的文件夹再升级。装在不可写位置时，应用内更新会失败。

覆盖后若仍看到旧版本，多半是开了另一份 `Snapover.exe`。在资源管理器里对正在用的快捷方式选「打开文件所在的位置」，确认替换的是这一份。

## 装好后检查

1. 设置 → 关于与更新：版本号正确。需要的话打开「自动检查更新」。
2. 连接设备：已配对电脑还在。没有的话不要重新生成身份，先确认数据目录没被换掉或清空。
3. 复制一条文字，看对端是否同步。
4. Mac 再试一次快速历史快捷键。提示没有辅助功能权限就按上一节重新允许。
5. 用过 CLI 的话，确认新包里的 `snapover-cli` / `snapover-cli.exe` 也一起换了。Mac 的 CLI 在 `Snapover.app/Contents/Resources/snapover-cli`。

## 常见问题

**点了检查更新没反应，或提示不能自动更新。**  
从 `.dmg` 里直接运行、放在只读位置，或不是正式打包的程序，都不会自己升级。按本文手动装到「应用程序」或可写的 Windows 目录。

**更新后快捷粘贴或发现设备不行。**  
先完全退出再打开。仍不行就重新允许辅助功能和本地网络。不要删数据目录。

**两台电脑版本不一样。**  
已有配对通常还能重连。第一次配对必须两边都是能完成确认的版本。功能对不齐时，两边都装到同一版。

**想装回旧版。**  
不建议。旧安装包不会改数据目录位置，但新版可能已经改过历史或设置格式。一定要回退的话，先备份整个数据目录。

**下载了 `.tar.gz` 不知道怎么用。**  
那是给应用内更新器用的。Mac 手动升级用 `.dmg`。Windows 手动升级优先用 ZIP；只有手头只有 `.tar.gz` 时，再解压后覆盖 `Snapover.exe` 和旁边的资源文件。

**发布页上的 Source code 要不要下。**  
不要。那是 GitHub 自动附带的源码包，不是安装包。
