# 2026-10-16 性能与内存修复

针对全项目审计的两处功能缺陷、一处通知留存及三组交互瓶颈。保留原有配对、协议、历史文件及剪贴板持久化行为；没有增加运行时依赖。工作区原有的 MyGo v0.5.5 升级和阻塞诊断仍保留。

## 已完成

| 问题 | 修改后的行为 |
| --- | --- |
| 远端回读误吞新复制 | 删除写后 Snapshot 和 suppressSeq；仅标记实际写入的内容。准备图片前记录序号，发布前重新验证，新的本地复制优先。 |
| 远端图片被监听器重复处理 | 同一次原生发布附带进程级远端标记。监听器先检查小标记和序号，跳过自身写入；读取过程中序号改变则重新采集。 |
| 原生图片转换阻塞 UI | macOS 原生取 PNG / TIFF 字节，在后台解码 TIFF；不走 MyGo 会自动转换 TIFF 的便携 PNG 读取接口。Windows 在后台读取 PNG / DIB、转换并准备 HGLOBAL；主线程仅接管原生缓冲区，同时发布 PNG 与兼容的 CF_DIB。 |
| 大图并发放大峰值 | 捕获、接收和历史粘贴的完整解码共用一个额度；解码缓冲上限 160 MiB，原生数据在复制到 Go 前限长。原有 PNG 20 MB、4000 万像素限制仍在。 |
| 每次大图后强制 GC | 大图结束后等待约 2 秒空闲再归还内存，至少相隔 15 秒，不与该额度内的解码同时执行。 |
| 主窗口关闭后清理状态不恢复 | 清理结果由应用级回调收尾，快捷历史也可消费完成结果；不依赖设置窗口持续渲染。 |
| 历史磁盘锁拖住列表 | 历史元数据发布到独立快照；List 不再等待存储写锁。历史置顶、删除、清空统一后台执行，错误仍在操作界面显示。 |
| 反复开关历史叠加粘贴准备 | 全应用最多一个准备任务，另只保留一次最新粘贴意图；关闭窗口取消结果发布，旧准备完成并释放资源后自动处理最新请求。Windows 预备原生缓冲在取消或失败时显式释放。 |
| 文件通知持续留存 | 单后台通知任务、最多 16 条待显示及 16 条保留；复用固定 ID，淘汰时 Close 释放对象和回调，退出时清理。 |
| 面包屑逐条 Sync、日志不轮转 | 普通诊断使用最多 256 条的非阻塞队列，后台写入并通常每秒 Sync；队列满丢普通诊断。退出及显式阻塞栈等待刷盘，运行时按约 1 MiB 轮转，保留上一份。致命运行时错误直接写文件。 |
| 快捷粘贴主线程 Sleep | 80 ms 关闭过渡、60 ms 焦点等待在后台计时，主线程分别执行激活与按键发布；重新检查前台目标，用户重开历史或退出可取消旧请求。 |

160 MiB 是单份解码像素缓冲上限，不是整个进程的 RSS 上限。特别大的 16 位 RGBA 图片会被更早拒绝。系统剪贴板自身持有的像素、编码字节、原生缓冲和 Go 保留堆仍会占用内存。

Windows 使用隐藏的消息窗口作为原生剪贴板 owner，依托现有 UI 循环，不创建轮询线程或延迟渲染 provider。HGLOBAL 在后台准备，发布成功后由系统接管；未发布部分由 PreparedWrite.Close 回收。遵循 [SetClipboardData 的所有权及内存要求](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setclipboarddata)。

## 修改前后对照

本机 Apple M4 / macOS arm64 / Go 1.27.2。对照基准为 `BenchmarkReceivedLargeImage`：4000×10000 合成 PNG，解码后交给同步引擎；测试剪贴板的 Snapshot 模拟完整图片回读。旧引擎通过临时 Go overlay 读取修改前的 `ea75a27` 版本，其他代码和样本相同，每组 5 次。

| 项目 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 解码与交付耗时 | 531.44 ms/op | 265.57 ms/op |
| 累计 Go 分配 | 329,343,720 B/op（314.09 MiB） | 164,675,107 B/op（157.05 MiB） |
| 分配次数 | 390,588 /op | 195,305 /op |

该基准耗时和累计分配均降低约 50%。它不包含网络、真实系统剪贴板发布、Watch 的额外回声读取或 GPU 绘制，不能解释成“整机内存减半”或“Windows 实测快一倍”。监听器额外读取的消除另有回归测试验证。

## 验证

- 全量 `go test ./... -count=1`。
- `go test -race ./cmd/... ./internal/... -count=1`。
- macOS 和 Windows 目标的 `go vet`。
- Windows amd64 全部测试包交叉编译；这是编译检查，没有在 Windows 上执行。
- `SNAPOVER_TEST_UI=1 go test ./cmd/snapover -run '^TestMainWindow' -count=1 -timeout 45s`：真实 macOS 窗口关闭 / 重开、独立快捷历史及无主窗口时的维护收尾。
- macOS 私有命名 pasteboard 上测试实际 PNG / TIFF 原生读取；不改动用户的通用剪贴板。
- 回归覆盖：写入后立即发生本地复制、准备期间的新复制、读取时序号变化、远端图片跳过 Snapshot、Windows 标记尾部填充、DIB 24/32 位行序和 V5 透明度、非法尺寸与掩码、16 位解码预算、列表不等待写锁、取消粘贴、通知淘汰与退出清理、诊断队列满及运行期轮转。

## 验证边界

尚无 Windows 实机原生剪贴板交互与跨设备连续大图测试，也未做数小时驻留测试。Windows 原生适配层通过交叉编译、静态检查及共用转换代码测试；仍需在 Windows 上验证截图、常用应用粘贴、占用重试和退出后内容持久化。

普通复制的 50 ms 轮询与 150 ms 稳定等待保留，以免 Excel、Figma 等更新多种剪贴板格式时重复同步。原生数据提供方本身不返回、磁盘损坏或权限被拒绝仍可能影响操作；这些不能靠减少解码次数消除。
